Random utility model


The utility for alternative \(j\) is
\[\tilde{u}_j = v_j + \tilde{\varepsilon}_j\]
\(v_j\) = Things we observe (non-random variables)
\(\tilde{\varepsilon}_j\) = Things we don’t observe (random variable)

\[\tilde{u}_j = v_j + \tilde{\varepsilon}_j\]

Practice Question 1

  1. A random variable, \(\tilde{x}\), has the PDF, \(f_{\tilde{x}}(x)\). Write the equation to compute its total probability (hint: think area under the curve!). What is the answer to the equation?
  1. A random variable, \(\tilde{x}\), has a uniform distribution between the values 0 and 1. Draw the probability density function (PDF) and Cumulative Density Function (CDF) of \(\tilde{x}\).
  1. The value of a random variable, \(\tilde{x}\), is determined by rolling one fair, 6-sided dice. Draw the PDF and CDF of \(\tilde{x}\).

Logit model: Assume that \(\tilde{\varepsilon}_j\) ~ Gumbel Distribution

\[\tilde{u}_j = v_j + \tilde{\varepsilon}_j\]
Probability of choosing alternative \(j\):
\[P_j = \frac{e^{v_j}}{\sum_k{e^{v_k}}}\]

Practice Question 2

a) A consumer is making a choice between two bars of chocolate:

  • Milk chocolate \((m)\)
  • Dark chocolate \((d)\)

Assume that we know the observed utility of each bar to be \(v_m = 3\) and \(v_d = 4\). Using a logit model, compute the probabilities of choosing each bar: \(P_m\) and \(P_d\).

b) A third bar of chocolate is now added to the choice set. It is the exact same as the milk chocolate bar, but it has a slightly different wrapper (which has no effect on the consumer’s utility). Now, \(v_{m1} = v_{m2} = 3\), and \(v_d = 4\). Based on the probabilities from question a), what would we expect the probabilities of choosing each bar to be? What probabilities does the logit model produce?

“Observed utility” \((v_j)\) is a weighted sum of attribute values


\[v_j = \beta_1 x_{j}^{\mathrm{A}} + \beta_2 x_j^{\mathrm{B}} + \dots\]

Each \(x_j\) is an observable attribute (price, etc.)


We know \(x_{j}^{\mathrm{A}}, x_{j}^{\mathrm{B}}, \dots\),
we want to estimate \(\beta_1, \beta_2, \dots\)

Notation Convention

Continuous: \(x_j\)
\[u_j = \beta_1 x_{j}^{\mathrm{price}} + \dots\] 
#>   price
#> 1     1
#> 2     2
#> 3     3
Discrete: \(\delta_j\)
\[u_j = \beta_1 \delta_{j}^{\mathrm{ford}} + \beta_2 \delta_{j}^{\mathrm{gm}} \dots\] 
#>   brand brand_BMW brand_Ford brand_GM
#> 1  Ford         0          1        0
#> 2    GM         0          0        1
#> 3   BMW         1          0        0

Dummy-coded variables

Dummy coding: 1 = “Yes”, 0 = “No”

Data frame with one variable: price

data <- data.frame(
  price = c(10, 20, 30)
)

data

#> 1    10

#> 3    30

Add dummy columns for each price “level”

library(fastDummies)

dummy_cols(data, "price")
#>   price price_10 price_20 price_30
#> 1    10        1        0        0
#> 2    20        0        1        0
#> 3    30        0        0        1
Model price as continuous

\(v_j = \beta_1 x^\mathrm{price}\)

model <- logitr(
    data = data,
    choice = "choice",
    obsID = "obsID",
    pars = "price"
)


Coef. Interpretation
β1 how utility changes with increasing price
Model price as discrete

\(v_j = \beta_1 \delta^\mathrm{price = 20} + \beta_2 \delta^\mathrm{price = 30}\)

model <- logitr(
    data = data,
    choice = "choice",
    obsID = "obsID",
    pars = c("price_20", "price_30")
)

Reference level: price=10

Coef. Interpretation
β1 utility for price=20 relative to price=10
β2 utility for price=30 relative to price=10

Dummy coding categorical variables with cbc_encode()

Standard coding (human-readable)

design |>
  select(altID, powertrain)
#>   altID powertrain
#> 1     1   Gasoline
#> 2     2     Hybrid
#> 3     3   Electric

Dummy coding (what logitr() needs)

design |>
  cbc_encode(coding = "dummy") |>
  select(altID, starts_with("powertrain"))
#>   altID powertrainHybrid powertrainElectric
#> 1     1                0                  0
#> 2     2                1                  0
#> 3     3                0                  1

Rule:
Use dummy_cols() for any data frame
Use cbc_encode() for data made with {cbcTools}.

Choosing the reference level

Default: first level is the reference

cbc_encode(
  design,
  coding = "dummy"
)

\(v_j = \beta_1 \delta^\mathrm{hybrid} + \beta_2 \delta^\mathrm{electric}\)

Coef. Interpretation
β1 utility of Hybrid relative to Gasoline
β2 utility of Electric relative to Gasoline

Pick a different reference level:

cbc_encode(
  design,
  coding = "dummy",
  ref_levels = list(powertrain = "Electric")
)

\(v_j = \beta_1 \delta^\mathrm{gasoline} + \beta_2 \delta^\mathrm{hybrid}\)

Coef. Interpretation
β1 utility of Gasoline relative to Electric
β2 utility of Hybrid relative to Electric

)

Not sure what coefficients to use?

cbc_suggest_priors() proposes a starting point based on your attribute levels

cbc_suggest_priors(profiles)
priors <- cbc_priors(
  profiles = profiles,
  price = -0.065,
  fuelEconomy = 0.065,
  accelTime = -0.325,
  powertrain = c(
    Hybrid = 0.2,
    Electric = -0.4
  )
)

These are only a starting point:

  • Continuous attributes get small, same-sized effects
  • Categorical levels are relative to the reference level
  • Signs are all positive, so flip them where you expect a negative effect (e.g. price)
  • Adjust using your own domain knowledge
